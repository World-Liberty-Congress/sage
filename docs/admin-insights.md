# Admin insight tools in the web runtime

Admin Conversations expose three read capabilities through existing controls. `read_audit_log` requires Config; `read_usage` and browser-backed `read_conversations` require Database. Registration and execution enforce approved Admin authority. User and impersonated sessions do not receive these tools.

`read_audit_log` calls the Python control plane at `POST /internal/agent/admin-config/read-audit-log`. The internal token and live Admin actor are required. Filters cover a timestamp interval, actor, action source and setting key. Whole-record pages mask historical secrets and return a continuation bound to the filters. The Admin AI Config HTTP write handlers use the same audited mutation function as `update_agent_settings`: `admin_ui` distinguishes page writes from `sage_conversation`. A failed audit attempts compare-and-restore rollback without overwriting a concurrent change.

`read_usage` aggregates retained Postgres messages joined to owned web sessions. It validates current User IDs and provisioned test provenance through `POST /internal/agent/admin/usage-users` in batches of at most 200. No profile plaintext is returned. Explicit `[start,end)` timestamps and an IANA timezone determine inclusion and day buckets. User groups rank by total human-plus-assistant messages, then User ID. Tokens come from recorded Model usage observations, deduplicated per message/step/attempt; missing or conflicting values remain unknown. Future assistant metadata and observations carry `model` and `model_source=request`. These identify the requested model, not provider-confirmed billing identity. Costs remain unavailable without recorded versioned prices.

`read_conversations` uses the existing turn-scoped browser request registry. The chat request advertises `conversation_lookup`; Sage emits `conversation_lookup_request` and receives `POST /llm/chat/conversation-lookup-result`. The browser calls Python's Admin cookie/CSRF-protected `/admin/conversation-lookup/projection` and `/session`, decrypts retained review ciphertext with the live signer, and returns bounded text and feedback. Exact time filtering uses message timestamps inside ciphertext. The backend never falls back to raw Sage message content after review deletion.

All pages fit 1,200 UTF-8 bytes, include coverage and continuation, and preserve valid JSON. Browser replies are bound to the Admin session fingerprint, nonce, conversation, turn and pending call; expiry, cancellation, credential changes and conflicting replays reject replies. Conversation tool plaintext reaches the model for the current answer but is excluded from raw tool traces and tool-result memory. Answers may themselves quote selected text, as requested by the Admin.

Verification spans the narrow Python APIs, temporary Postgres tables, browser encryption/transport tests, shared audited-write rollback tests, and the parent application's isolated Compose acceptance and production release checks. The parent contract is `docs/contracts/admin-insights.md` in the pinned application repository.
